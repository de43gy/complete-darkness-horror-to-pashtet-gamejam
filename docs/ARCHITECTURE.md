# Техническое описание проекта

Описание того, что реально есть в коде на данный момент. Замысел игры целиком — в [CONCEPT.md](CONCEPT.md).

## Запуск

- Движок: Godot 4.7 (рендерер GL Compatibility). В более старых версиях проект может не открыться.
- Открыть `project.godot` в редакторе и нажать F5.
- Главная сцена: `res://scenes/main_menu/main_menu.tscn`.
- Окно 800×600, режим растяжения `viewport`.

Тесты логики (из папки проекта, код возврата 0 — всё прошло):

```
godot --headless res://tests/run_tests.tscn
```

## Управление

| Клавиши | Действие | Действие в `project.godot` |
|---|---|---|
| Стрелки | Шаг на одну клетку | `move_up`, `move_down`, `move_left`, `move_right` |
| Shift + стрелка | Пощупать клетку | `action_probe` |
| Ctrl + стрелка | Топнуть / пнуть | `action_stomp` |
| Пробел + стрелка | Прыжок через клетку | `action_jump` |
| Esc | Вернуться в меню | `ui_cancel` (встроенное) |
| Enter | Новый уровень (отладка) | `debug_new_level` |
| F1 | Показать или скрыть карту (отладка) | `debug_reveal_level` |

Направления в сообщениях: вверх по экрану — «вперед», вниз — «назад».

## Главная идея устройства

Логика игры отделена от картинки.

- **`core/`** — чистая логика: уровень, генераторы, правила действий. Здесь нет узлов сцены,
  координаты — клетки (`Vector2i`). Этот код проверяется тестами без запуска игры.
- **`content/`** — тексты лога.
- **`scenes/`** — всё, что видно на экране и принимает ввод. Сцены спрашивают логику
  «что произошло» и показывают результат.

Один ход игрока проходит так:

1. `Game` получает нажатие и определяет направление и вид действия.
2. `Explorer` применяет правило и возвращает `ActionResult` (что произошло).
3. `Messages` превращает `ActionResult` в строку для лога.
4. `Game` двигает спрайт девочки и отдаёт строку в `MessageLog`.

## Логика (`core/`)

### Level

Уровень как данные: `width`, `height`, `entrance_cell`, `exit_cell`, `generation_seed` и сетка
клеток. Размер задаётся при создании и может быть любым.

- Типы клеток — перечисление `Level.Cell`: `WALL`, `FLOOR`, `ENTRANCE`, `EXIT`.
- `get_cell(Vector2i)` — всё за пределами сетки считается стеной. Уровень непрямоугольной формы
  делается так же: лишнее просто остаётся стеной.
- `is_walkable(cell)`, `has_path()` (можно ли дойти от входа до выхода).
- `Level.from_rows([...])` собирает уровень из строк текста (`#` стена, `.` пол, `S` вход,
  `E` выход) — для тестов и уровней, нарисованных вручную.

### Генераторы

- `LevelGenerator` — абстрактный базовый класс. Новый паттерн генерации — это класс-наследник
  с двумя методами: `get_display_name()` и `generate(width, height, rng)`.
- Вся случайность берётся из переданного `rng`, поэтому одно и то же зерно всегда даёт один
  и тот же уровень. Снаружи вызывается `generate_from_seed(width, height, seed)`.
- `ClassicMazeGenerator` — классический лабиринт: обход в глубину с возвратом по клеткам
  с нечётными координатами. Вход внизу, выход вверху. Лучше всего работает с нечётными
  размерами; при чётном размере крайний столбец или строка остаётся сплошной стеной.

Чтобы новый генератор появился в стенде, его нужно добавить в список `generators`
в `scenes/generator_lab/generator_lab.gd`.

### Explorer и ActionResult

`Explorer` хранит уровень и клетку, где стоит девочка. Методы `step`, `probe`, `stomp`, `jump`
принимают направление и возвращают `ActionResult`:

| Поле | Смысл |
|---|---|
| `action` | `STEP`, `PROBE`, `STOMP`, `JUMP` |
| `outcome` | `BLOCKED` — стена вплотную; `MOVED` — переместилась; `CUT_SHORT` — прыжок оборван стеной; `SENSED` — узнала, что в клетке |
| `cell` | тип клетки, о которой результат: куда встала или что нащупала |
| `from_cell`, `to_cell` | где была и где оказалась |

Правила прыжка: стена вплотную — прыжок не состоится; стена через клетку — девочка приземляется
на клетку перед ней; иначе перелетает на две клетки.

### Memory

`Memory` хранит клетки, которых девочка касалась, и номер хода, когда это было. Принадлежит
`Explorer` (`explorer.memory`), который сам записывает в неё всё, чего коснулось действие:
клетку, о которой результат (нащупанную или стену, в которую ткнулась), клетку, с которой
сошла, и клетку, на которой стоит. Клетка, через которую она перепрыгнула, не запоминается.

- `duration` — сколько ходов клетка держится в памяти (не меньше 1). При значении 1 видно
  только то, что узнано после последнего хода.
- Ход памяти — это `step` или `jump`, в том числе неудачные (упёрлась в стену). `probe`
  и `stomp` ход не тратят: то, что ими узнано, держится до следующего движения.
- `get_strength(cell)` — от 1.0 (только что) до 0 (вот-вот забудет); по нему отрисовка
  делает старые клетки бледнее.
- В игре длительность задаётся параметром `memory_duration` сцены `game.tscn`.

## Тексты (`content/messages.gd`)

`Messages.TEXTS` — словарь «событие → список вариантов фразы». Ключ события складывается из
действия и исхода: `step.floor`, `probe.wall`, `jump.cut_short` и так далее. Из вариантов
выбирается случайный, `{dir}` заменяется названием направления. Чтобы добавить вариант фразы,
достаточно дописать строку в список.

## Сцены

| Сцена | Назначение |
|---|---|
| `main_menu/main_menu.tscn` | Меню: начать игру, генератор уровней, выход |
| `game/game.tscn` | Игра. Скрипт `game.gd` (`Game`) создаёт уровень, обрабатывает ввод. Размер уровня и стартовое открытие карты — экспортируемые параметры |
| `game/level_view.gd` | `LevelView` — рисует уровень, подстраивает свой размер под него. Параметры: `cell_size`, `revealed`, `show_grid`, `memory` |
| `game/girl.tscn` | `Girl` — спрайт девочки с анимациями ходьбы |
| `game/message_log.tscn` | `MessageLog` — лог: новое сообщение сверху, старые бледнеют, не больше 6 строк |
| `generator_lab/generator_lab.tscn` | Стенд: выбор генератора, ширины, высоты и зерна; карта показана целиком и вписывается в экран |

`LevelView` показывает клетку одним из двух способов:

- **видимая** — в цвете (`SEEN_COLORS`). Пока это только отладочный режим `revealed`; позже
  здесь источники света и поле зрения будут решать, какие клетки освещены;
- **нащупанная** — чёрно-белая, из памяти девочки (`memory`), чем старее — тем бледнее. Типы
  клеток различаются формой, а не оттенком, чтобы бледная клетка не выглядела как другая:
  стена — сплошной блок, пол — контур, ступеньки — контур с треугольником (вверх — путь назад,
  вниз — спуск).

Всё остальное остаётся чёрным.

## Принятые соглашения

- **Клетки, а не пиксели.** Вся логика работает с `Vector2i`. В пиксели клетку переводит только
  `LevelView.cell_to_position()`.
- **Логика не знает о сценах.** Код в `core/` и `content/` не обращается к узлам, вводу и логу.
- **Ссылки на узлы** — через уникальные имена (`%LevelView`), без групп и глобальных переменных.
- **Сообщения** — от первого лица девочки, в формате `"- текст."`, только в `messages.gd`.
- **Типизация.** Включены предупреждения `untyped_declaration` и `inferred_declaration`: у всех
  переменных, параметров и функций указан тип явно (без `:=`).
- **Случайность уровней** — только через `rng` генератора, чтобы уровень воспроизводился по зерну.

## Известные недоделки

- Дойдя до выхода, игрок получает только сообщение; перехода на следующий уровень нет.
- Света и поля зрения нет: видны только клетки из памяти либо вся карта целиком (F1).
- Спрайт девочки выше клетки и закрывает собой клетку над ней — стену, нащупанную сверху, за ним не видно.
- Анимация `idle` не проигрывается: после действия остаётся последняя анимация ходьбы.
- Уровень рисуется цветными прямоугольниками, тайлсета нет.
- Уровень крупнее экрана в игре не помещается: камеры, следящей за девочкой, нет.
- Генератор один.
- Нет звука, сохранений, экрана окончания игры.
