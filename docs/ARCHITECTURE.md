# Техническое описание проекта

Описание того, что реально есть в коде на данный момент. Замысел игры целиком — в [CONCEPT.md](CONCEPT.md).

## Запуск

- Движок: Godot 4.5 или новее (проверено на 4.7), рендерер GL Compatibility.
- Открыть `project.godot` в редакторе и нажать F5.
- Главная сцена: `res://scenes/ui/game_menu/game_menu.tscn`.
- Окно 800×600, режим растяжения `viewport`.

## Управление

| Клавиши | Действие | Функция в `player.gd` |
|---|---|---|
| Стрелки | Шаг на одну клетку | `try_move` |
| Shift + стрелка | Пощупать клетку | `probe_cell` |
| Ctrl + стрелка | Топнуть / пнуть | `stomp_cell` |
| Пробел + стрелка | Прыжок на две клетки | `jump_cell` |
| Enter на цифровой клавиатуре | Сгенерировать лабиринт заново (отладка) | `Labyrinth._input` |

Действия `ui_shift`, `ui_ctrl` и `ui_new_key` заданы в `project.godot`; для прыжка используется
стандартное `ui_select`.

Направления в сообщениях: вверх по экрану — «вперед», вниз — «назад».

## Сцены и скрипты

### Поток сцен

`game_menu.tscn` → кнопка «Начать игру» → `game_scene.tscn`.

### GameScene (`scenes/main/game_scene/`)

Корневой контроллер игровой сцены. В `_ready()` собирает ссылки на `Labyrinth`, `MessageLog`
и `UserInterface`, перебирая узлы группы `game_elements`. Больше пока ничего не делает —
это место для будущей логики уровня (переход на следующий уровень, страх, награды).

### Labyrinth (`scenes/main/labyrinth/`)

- `labyrinth.tscn`: корень — `ColorRect`, внутри `Node2D` со скриптом `labyrinth.gd`, внутри него
  `LabyrinthContainer` (`ColorRect` со скриптом `labyrinth_container.gd`).
- `labyrinth.gd` (`class_name Labyrinth`) — порядок генерации в `generate_maze()`:
  1. `ClassicMazeGenerator.generate_classic_maze()` — прорезает лабиринт;
  2. `ensure_border_walls()` — закрывает периметр стенами;
  3. `MazeEntranceExit.create_entrance_and_exit()` — прорезает вход и выход;
  4. `create_collision_walls()` — расставляет `StaticBody2D` по стенам;
  5. `spawn_player()` — создаёт персонажа (один раз) и ставит его на вход.
- `labyrinth_container.gd` (`class_name LabyrinthContainer`) — рисует лабиринт в `_draw()`:
  стены чёрные, проходы белые, вход зелёный, выход красный. **Это отладочный вид** — по концепту
  карта должна быть полностью чёрной. Экспортируемый флаг `show_grid` включает сетку.

Объекты столкновений создаются один раз (по одному на клетку) и затем только показываются или
скрываются. На движение персонажа они сейчас не влияют: проходимость проверяется по массиву
лабиринта.

### Player (`scenes/entities/player/`)

`player.gd` (`class_name PlayerScene`), `CharacterBody2D` с `AnimatedSprite2D`
(анимации `idle`, `walk_up`, `walk_down`, `walk_left`, `walk_right`).

- Ввод обрабатывается в `_unhandled_input`. Движение дискретное: позиция меняется сразу на
  целую клетку, физика не используется.
- `get_cell_content(pos)` переводит пиксельную позицию в клетку и возвращает
  `CellContent`: `WALL`, `EMPTY`, `ENTRANCE` или `EXIT`. Всё за пределами массива считается стеной.
- Правила прыжка: если соседняя клетка — стена, прыжок не состоится; если стена через клетку,
  девочка приземляется на клетку перед ней; иначе перелетает на две клетки.
- Каждое действие пишет сообщение в `MessageLog`.

### MessageLog (`scenes/ui/message_log/`)

`message_log.gd` (`class_name MessageLog`), `RichTextLabel`. `log_message(text)` добавляет строку
наверх; хранится не больше `MAX_LINES` (6) строк, каждая следующая бледнее на `OPACITY_STEP`.
Текст переводится в верхний регистр и выводится по центру.

### UserInterface (`scenes/ui/user_interface/`)

Заготовка: пять отладочных кнопок и пять сигналов (`generate_maze`, `ensure_borders`,
`create_entrance_exit`, `check_create_path`, `clear_maze`). Кнопки ни к чему не подключены.

### Генерация лабиринта (`scripts/utilities/maze_generators/`)

| Файл | Назначение |
|---|---|
| `maze_constants.gd` | Автозагрузка `MazeConstants`: размеры, типы клеток, позиции входа и выхода |
| `maze_array.gd` | `MazeArray` — статическое хранилище сетки (`maze[y][x]`) и массива посещённых клеток |
| `generated_classic_maze.gd` | `ClassicMazeGenerator` — поиск в глубину с возвратом по клеткам с нечётными координатами |
| `maze_entrance_exit.gd` | `MazeEntranceExit` — вход внизу по центру, выход вверху по центру |

Константы `MazeConstants`:

```gdscript
WIDTH = 20        # ширина лабиринта в клетках
HEIGHT = 15       # высота в клетках
CELL_SIZE = 16    # пикселей на клетку
TIMEOUT = 1000    # лимит времени генерации, мс

WALL = 1
PATH = 0
TRAP = 2          # не используется
MONSTER = 3       # не используется
TREASURE = 4      # не используется
```

Особенности текущего генератора:

- Ширина чётная (20), а генератор работает по нечётным координатам, поэтому столбец 18 всегда
  остаётся сплошной стеной — лабиринт фактически на клетку уже поля.
- Вход и выход прорезаются в чётном столбце 10 и соединяются с лабиринтом через соседние
  клетки. Из-за этого возле входа и выхода может получаться петля.
- При срабатывании таймаута генератор просто прекращает работу; запасной «простой» генерации,
  о которой говорит сообщение в консоли, нет.

## Принятые соглашения

- **Связи через группы.** Компоненты находят друг друга через группу `game_elements`, а не по
  путям узлов. Чтобы `GameScene` или `Player` увидели новый компонент, узел **со скриптом**
  должен состоять в этой группе.
- **Доступ к лабиринту** — только через `MazeArray.get_maze_array()` / `set_maze_array()`.
  Индексация `maze[y][x]`.
- **Сообщения** игроку — через `MessageLog.log_message()`, на русском, от первого лица девочки,
  в формате `"- текст."`.
- **Типизация.** В проекте включены предупреждения `untyped_declaration` и `inferred_declaration`.
  Старый код в основном без аннотаций типов и даёт предупреждения; новый код стоит писать
  с типами.

## Известные недоделки

- Карта и персонаж видны (отладочный вид), темноты ещё нет.
- Дойдя до выхода, игрок получает только сообщение; перехода на следующий уровень нет.
- Отладочные кнопки `UserInterface` не подключены, их подписи на английском.
- Объекты столкновений стен создаются, но не используются.
- Анимация `idle` не проигрывается: после действия остаётся последняя анимация ходьбы.
- В `MazeConstants` остались неиспользуемые `message_log` и сигнал `message_log_set`,
  в `MazeArray` — неиспользуемый флаг `is_initialized`.
- Нет звука, сохранений, экрана окончания игры.
